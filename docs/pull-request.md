# Consolidate the open pull requests and work through the issue backlog

## Summary

This branch merges the code of all five open pull requests, integrates the preview task-list
contribution offered in #212, and fixes the concrete, reproducible defects of the open issue backlog.
It also removes signing data from the Xcode project so that a local build no longer needs a tracked
file to be edited, and adds the documentation set under `docs/`.

- **5 of 5** open pull requests integrated, their individual commits preserved.
- **24 issues fixed** in code, each with a test where the behavior is testable without a device.
- **Every open issue triaged** in [`docs/issue-triage.md`](issue-triage.md): fixed, already available,
  needs information, or deferred with a reason.
- **No personal signing data** in any tracked file or commit; see
  [`docs/local-signing.md`](local-signing.md).
- **AI-generated:** all code, tests and documentation in this branch were written by an AI coding
  agent (BuffY, running inside Freebuff/Codebuff).

## Native formatting, session persistence and the header

**The editor shows formatted text.** The delimiters of the inline elements are hidden on screen: `**bold**`
reads as **bold**, `==highlight==` as a highlight, `` `code` `` as monospaced text, `~~gone~~` struck
through, and the `#` of a heading is hidden too. They stay hidden while editing, so the note never shows
its Markdown; the characters remain in the text, so the server still receives `**bold**`. The hiding runs
at the end of the styling pass, after list and checkbox styling, which would otherwise restore the font
over the delimiter characters.

**Signing in survives a restart.** The account password was stored with the default `whenUnlocked`
accessibility; after a reboot or while the device was locked, the first synchronization read an empty
keychain, treated the account as signed out and surfaced `401` and "Not logged in". It is now stored
`afterFirstUnlock`, so the account is readable as soon as the device has been unlocked once.

**The note list uses a large title** instead of the inline one, so the page has a heading of its own and
the bar keeps room for search, sorting and the new-note button.

### How the merges were done

Each pull request was fetched from its own head (`git fetch origin pull/<n>/head:pr-<n>`) and merged
with `--no-ff`, so the original commits and their authorship stay intact and every PR remains
traceable. Conflicts were resolved by hand, keeping both sides' intent:

- **`Source/AppDelegate.swift` (#230 × main).** `main` had moved the note upload into an async `Task`;
  #230 wrapped the security-scoped access in `defer` and only deleted the temporary `Documents/Inbox`
  copy. Both are kept: the async upload, the `defer` that always stops accessing, and the Inbox check.
- **`Nextcloud/Viewer/NCViewerNextcloudText/NCViewerNextcloudText.swift` (#193 × main).** `main` had
  gained `isLoaded`/`isClosed` state, a load timeout, an error alert and `viewUnload(completion:)`;
  #193 added the swipe recognizer and the slide animator. The swipe handler is kept and calls the
  existing `close()`, which first asks the editor page to save, instead of dismissing directly. The
  `completion` parameter of `viewUnload` is preserved because the "Switch to Internal Editor" action
  depends on it.
- **`iOCNotes/Views/NotesPresenter.swift` (#193 × main).** `main` loads the collaborative editor through
  an async `loadLink` closure and reports failures itself; #193 replaced that with a synchronous link and
  a custom transition. The async loading and the error handling are kept, and only the presentation
  style changes to `.custom` with the viewer as transitioning delegate.
- **`Utils/KeychainHelper.swift` (#230 × #202).** Independent hunks (sync-on-start default vs. category
  grouping default), merged without edits.
- **`Source/EditorViewController.swift` (#229, #193, #233).** #229 rewrote the list editing and removed
  the debug loops, #193 added the back swipe, #233 added the formatting bar and removed the undo/redo bar
  buttons while editing. Git merged all three; the result was reviewed for coherence: one undo path (the
  formatting bar), one back gesture, one list handling.

## 4. Signing without personal data

The project used to hardcode a team identifier and the entitlements path, so building for a device meant
editing a tracked file — and a free "Personal Team" could not build at all, because registering
`group.com.nextcloud.apps` is only possible for a paid team.

- Shared defaults moved to `iOCNotes.xcconfig`, which ends with the optional `#include? "Local.xcconfig"`.
- `project.pbxproj` no longer contains `DEVELOPMENT_TEAM`, `CODE_SIGN_ENTITLEMENTS` or
  `PROVISIONING_PROFILE_SPECIFIER` (commit `b5ac5e3`).
- A developer who needs their own identity creates `Local.xcconfig` and, when the app group is
  unavailable, `Local.entitlements`. Both are untracked; the setup is described in
  [`docs/local-signing.md`](local-signing.md) with placeholders only.
- Without those files a normal checkout builds exactly as before, which the verification below checks.

## 8. How to verify

```
# Build for the simulator without any signing identity
xcodebuild build -project iOCNotes.xcodeproj -scheme iOCNotes \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO

# Run the unit tests on a booted simulator
xcodebuild test -project iOCNotes.xcodeproj -scheme iOCNotes \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  -parallel-testing-enabled NO CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual DEVELOPMENT_TEAM=
```

Manually:

1. Open a note and delete it from the "More" menu — it disappears and the list no longer shows it.
2. Open a note with categories and tap a category header twice — the rows collapse and expand.
3. Type continuously for a few seconds against a slow server — no "Error updating note" flood.
4. Open the preview of a note with a checklist and tick a box — the editor content changes and stays.
5. Pull down the list in airplane mode — the banner appears at the top, hides itself, and can be
   dismissed.

## 9. Risks and limitations

- **Formatting bar on iPad.** The bar is an `inputAccessoryView`; with a hardware keyboard it is not
  shown. Undo and redo live only in the bar now, so with a hardware keyboard use the system shortcut.
- **Write queue.** An update that fails while further edits are pending stops the loop; the note stays
  marked as pending and the next synchronization retries. This is intentional (no retry storm) but means
  a failure is not retried until then.
- **Titles.** The setting only affects notes created afterwards. Existing note names are never changed by
  editing, which is the reported expectation, but a note created before this change keeps its current
  title.
- **Preview checkboxes.** Ticking is disabled for read-only notes, and a note changed elsewhere while the
  preview is open makes the stale checkbox do nothing until the preview is reopened.
- **App group.** A build without the app group cannot read accounts shared by the Nextcloud iOS app.
- **Not fixed here:** swipe-down to close a note (#121 asks for it; the branch restores swipe-back),
  the remaining large features listed in the triage, and issues without a reproducible report.
